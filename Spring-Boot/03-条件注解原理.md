# 条件注解原理（@Conditional、@ConditionalOnClass 等）

> 条件注解是 Spring Boot 自动装配的"开关"。本文先讲清楚 `@Conditional` 的底层机制，再逐一列出 Spring Boot 提供的衍生注解，最后给出 **`ConditionEvaluator` 的评估时机** 和 **常见踩坑**。

---

## 一、`@Conditional`：Spring 原生

`@Conditional` 在 Spring 4 引入（不是 Spring Boot 的），定义如下：

```java
@Target({TYPE, METHOD})
@Retention(RUNTIME)
public @interface Conditional {
    Class<? extends Condition>[] value();
}
```

它要求传入一个或多个 `Condition` 接口的实现：

```java
public interface Condition {
    boolean matches(ConditionContext context, AnnotatedTypeMetadata metadata);
}
```

只要 `matches` 返回 `false`，**被标注的 `@Configuration` 类或 `@Bean` 方法就会被跳过**。

`ConditionContext` 提供：

- `BeanDefinitionRegistry`
- `ConfigurableListableBeanFactory`（可能为 null）
- `Environment`
- `ResourceLoader`
- `ClassLoader`

---

## 二、Spring Boot 提供的条件注解一览

所有衍生注解都基于 `@Conditional(XxxCondition.class)`，本质是给 `Condition` 实现起了个语义化名字。

### 1. Class 维度

| 注解                                | 条件                                                    |
| ----------------------------------- | ------------------------------------------------------- |
| `@ConditionalOnClass`               | classpath 中**存在**指定类                              |
| `@ConditionalOnMissingClass`        | classpath 中**不存在**指定类                            |

> 注意：因为参数是 `Class<?>`，加载注解时会触发类加载。为支持"指定类不存在"的场景，Spring Boot 还支持 `name` 属性（字符串形式），底层用 `ClassUtils.forName` 反射判断，避免类加载异常：
> ```java
> @ConditionalOnClass(name = "javax.servlet.Servlet")
> ```
> Spring Boot 自动装配大量使用 `name` 形式。

### 2. Bean 维度

| 注解                                | 条件                                                  |
| ----------------------------------- | ----------------------------------------------------- |
| `@ConditionalOnBean`                | 容器中**存在**指定 Bean                               |
| `@ConditionalOnMissingBean`         | 容器中**不存在**指定 Bean                             |
| `@ConditionalOnSingleCandidate`     | 容器中**恰好只有一个**指定类型 Bean（或带 `@Primary`）|

匹配支持多种条件维度：`value` (Class)、`type` (类名 String)、`name` (Bean name)、`annotation`、`ignored`、`search` (BeanFactory 搜索范围)。

### 3. 属性维度

| 注解                                | 条件                                                                  |
| ----------------------------------- | --------------------------------------------------------------------- |
| `@ConditionalOnProperty`            | 配置属性存在且值匹配                                                 |

典型用法：

```java
// my.feature=true 才生效；属性缺失时，默认 false → 不生效
@ConditionalOnProperty(prefix = "my", name = "feature", havingValue = "true")

// 配置缺失时也认为匹配 —— 默认开启
@ConditionalOnProperty(prefix = "my", name = "feature", havingValue = "true", matchIfMissing = true)
```

### 4. Web 类型维度

| 注解                                | 条件                                                  |
| ----------------------------------- | ----------------------------------------------------- |
| `@ConditionalOnWebApplication`      | 当前是 Web 应用（可指定 SERVLET / REACTIVE / ANY）     |
| `@ConditionalOnNotWebApplication`   | 不是 Web 应用                                         |

### 5. 资源 / SpEL / 表达式

| 注解                                | 条件                                                  |
| ----------------------------------- | ----------------------------------------------------- |
| `@ConditionalOnResource`            | classpath 下存在指定资源（如 `classpath:foo.properties`）|
| `@ConditionalOnExpression`          | SpEL 表达式为 true                                    |
| `@ConditionalOnJava`                | 当前 JDK 版本满足                                     |
| `@ConditionalOnJndi`                | 指定 JNDI 名称可定位                                  |
| `@ConditionalOnCloudPlatform`       | 在指定云平台（KUBERNETES、CLOUD_FOUNDRY 等）          |
| `@ConditionalOnWarDeployment`       | 以 war 形式部署在外部容器                             |

### 6. Native（Spring Boot 3 / GraalVM）

| 注解                  | 条件             |
| --------------------- | ---------------- |
| `@ConditionalOnNativeImage` | 当前是 native image 运行环境 |

## 三、`@Conditional` 是怎么被评估的？

核心类：**`org.springframework.context.annotation.ConditionEvaluator`**。

调用入口在 `ConfigurationClassParser`：

1. 解析 `@Configuration` 类时，**先评估类上的条件**：
   ```java
   if (this.conditionEvaluator.shouldSkip(metadata, ConfigurationPhase.PARSE_CONFIGURATION)) {
       return;  // 直接跳过这个配置类
   }
   ```
2. 解析其中的 `@Bean` 方法时，**再评估方法上的条件**：
   ```java
   if (this.conditionEvaluator.shouldSkip(metadata, ConfigurationPhase.REGISTER_BEAN)) {
       continue;  // 跳过该 @Bean
   }
   ```

### 两种 `ConfigurationPhase`

| 阶段                       | 含义                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `PARSE_CONFIGURATION`      | 解析阶段：BeanFactory 中可能还没有所有 Bean，因此只能基于 **classpath、Environment** 等可早期获取的信息判断           |
| `REGISTER_BEAN`            | 注册阶段：BeanFactory 中（理论上）已经有了所有 BeanDefinition，可以基于 **Bean 存在与否**（如 `OnBeanCondition`）判断 |

不同条件实现自己声明自己适用的阶段：

- `OnClassCondition` → `PARSE_CONFIGURATION`
- `OnBeanCondition` → `REGISTER_BEAN`
- `OnPropertyCondition` → `PARSE_CONFIGURATION`
- `OnWebApplicationCondition` → `PARSE_CONFIGURATION`

`ConditionEvaluator` 只在 **当前阶段** 评估匹配阶段相同的条件，避免过早判断。

## 四、自动装配里的"双重过滤"

参见 `01-Spring Boot 自动装配原理.md`：

1. **`AutoConfigurationImportFilter`** 在 import 阶段就尝试快速过滤，把肯定不满足 `@ConditionalOnClass`、`@ConditionalOnBean`、`@ConditionalOnWebApplication` 的配置类剔除，**避免类加载和 BeanDefinition 注册的开销**。
2. **`ConditionEvaluator`** 在 parse / register 阶段精细评估剩余条件。

这个二段式设计，让 Spring Boot 在 jar 包众多时启动依然可控。

## 五、常见踩坑

### 1. `@ConditionalOnMissingBean` 的顺序敏感

`@ConditionalOnMissingBean` 评估的是 **当前 BeanFactory 中已注册的 BeanDefinition**。如果用户的 `@Configuration` 比自动装配类后解析，它对自动装配中的 Bean 是"看不到"的。

Spring Boot 通过 `DeferredImportSelector` 把自动装配延后到所有用户配置之后处理，**保证用户 Bean 优先**。但如果两个自动装配类互相依赖，需要用 `@AutoConfigureBefore` / `@AutoConfigureAfter` 调整顺序。

### 2. `@ConditionalOnClass` 直接传 Class 会触发类加载

如果指定的类在 classpath 中不存在，配置类加载到 `@ConditionalOnClass(SomeClass.class)` 时会立刻 `NoClassDefFoundError`。

✅ 正确做法（自动装配里大量使用）：

```java
@ConditionalOnClass(name = "com.example.SomeClass")
```

或者把 `@ConditionalOnClass(SomeClass.class)` **写在配置类上**而不是 `@Bean` 方法上 —— Spring Boot 对配置类上的 `@ConditionalOnClass` 做了特殊处理，会先用字符串方式判断。

### 3. `@ConditionalOnProperty` 默认 "未配置时不生效"

`matchIfMissing` 默认 `false`，这意味着 **属性缺失 = 条件不匹配**。如果想 "默认开启，显式关闭" 的语义，必须显式写 `matchIfMissing = true`。

```java
@ConditionalOnProperty(prefix = "my", name = "enabled", havingValue = "true", matchIfMissing = true)
```

### 4. 自定义 `Condition` 时只能用 Environment / ClassLoader 等"早期可用"的信息

不要在 `Condition` 里依赖 `BeanFactory.getBean(...)`：

- `PARSE_CONFIGURATION` 阶段 BeanFactory 还未完成全部 BeanDefinition 注册。
- 即便能拿到 `BeanFactory`，调用 `getBean` 也会触发 Bean 实例化 —— 极易死锁或顺序错乱。

如需"基于 Bean 是否存在"，请直接用 `@ConditionalOnBean` / `@ConditionalOnMissingBean`，它们由 `OnBeanCondition` 处理，已声明为 `REGISTER_BEAN` 阶段。

## 六、自定义条件注解示例

```java
// 1. 实现 Condition
public class OnLinuxCondition implements Condition {
    @Override
    public boolean matches(ConditionContext context, AnnotatedTypeMetadata metadata) {
        String os = System.getProperty("os.name");
        return os != null && os.toLowerCase().contains("linux");
    }
}

// 2. 派生注解
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Conditional(OnLinuxCondition.class)
public @interface ConditionalOnLinux {
}

// 3. 使用
@Configuration
@ConditionalOnLinux
public class LinuxOnlyConfig {
    @Bean
    public InotifyWatcher watcher() { return new InotifyWatcher(); }
}
```

## 七、调试技巧

- 启动时加 `--debug`，看 `CONDITIONS EVALUATION REPORT` 的 Negative matches。
- 引入 Actuator 访问 `/actuator/conditions`。
- 给可疑的 `Condition` 实现继承 `SpringBootCondition`（Spring Boot 内置基类），它在 `getMatchOutcome` 返回 `ConditionOutcome` 时**会自动记录 message 到评估报告中**，定位问题非常方便：

```java
public class OnLinuxCondition extends SpringBootCondition {
    @Override
    public ConditionOutcome getMatchOutcome(ConditionContext context, AnnotatedTypeMetadata metadata) {
        String os = System.getProperty("os.name");
        ConditionMessage.Builder msg = ConditionMessage.forCondition("OnLinux");
        if (os != null && os.toLowerCase().contains("linux")) {
            return ConditionOutcome.match(msg.foundExactly(os));
        }
        return ConditionOutcome.noMatch(msg.didNotFind("linux").items(os));
    }
}
```
